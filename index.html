用中文問資料，
答案附上 SQL 與圖表

這是一個讓你用中文問資料庫的系統。你不需要先會 SQL——先看圖，再點、再試玩，就知道它在「寫 SQL 之前」和「執行 SQL 之前」各做了什麼把關。

💬 用中文提問→🧭 澄清、補脈絡、把關→📊 SQL ＋ 圖表
5組規則式澄清關鍵字（業績、排名、暢銷、大客戶、高薪）
0澄清步驟的模型呼叫次數（在初始化模型之前就回傳）
3每次最多注入的相似範例筆數（top-3；Schema 預選也取前 3 張表）
5個管理後台工作台：數據管理、樣本訓練、語意治理、數據建模、知識圖譜

01

先講人話：它在解決什麼？

資料在資料庫裡，但要查就得寫 SQL。這個系統讓你直接用中文問，並且把「怎麼查」攤開給你檢查。

😵 現況想知道「各部門平均薪資」，得先會寫 GROUP BY、JOIN，還要知道有哪些資料表。
🎯 目標用平常說話的方式問；Agent 自己看結構、寫 SQL、執行，並附上圖表。SQL 可檢視、可編輯。

03

一個問題的旅程

你在輸入框按下 Enter 之後，發生了什麼？點步驟看圖。

SSEthinking：正在執行工具
SSEtext：文字回答
SSEsql：執行的 SQL
SSEdata / chart：結果與圖表
SSEtitle、done：標題與結束

事件類型取自 chat.py 與 agent.py；澄清時改送 text → clarify → done，不進入模型。

05

試玩：問題會不會被反問？

下面這個判定器，是把 agent.py 裡的 5 組關鍵字與排除詞原樣搬過來：打一句話，看它會不會被反問。點選選項，會像真的一樣把選項當成新問題再判定一次。

規則來源：agent.py 第 70–138 行（關鍵字、排除詞、問句與選項逐字相同）；命中後送出 text、clarify、done 三個事件並結束，不呼叫模型。選項是內建範本，不依資料庫欄位產生。

08

怎麼跑起來？

本機開發：後端 FastAPI＋前端 Vite；雲端部署：單一 Docker 容器。以下依 README 與 Dockerfile 整理，本次未實際啟動。

  1. 後端：進 backend、建虛擬環境、pip install -r requirements.txt，再啟動服務（8000 埠）。
  2. 前端：進 frontend、npm install、npm run dev，打開 http://localhost:5173。
  3. 設定模型：左下角「設定模型供應商即金鑰」填對話模型與 API Key；Embedding 端點選填。金鑰存在 settings.db，不放進業務資料庫。
uvicorn app.main:app --reload --port 8000

於 backend/ 目錄執行。API 文件在 /docs，健康檢查在 /health。雲端：Dockerfile 兩階段（Node 20 建前端 → Python 3.11），PORT=7860，Hugging Face Spaces 需 README 前置設定 sdk: docker。

路徑（/api 之下）用途來源

/sessions…對話清單與訊息api/session.py
/database/upload · /tables · /er-model · /graph · /execute上傳資料、表清單、ER 模型、知識圖譜、手動執行 SQL（同樣過守衛）api/database.py
/samples · /semantics/mappings · /semantics/descriptions樣本、詞語映射、欄位描述的增刪查api/samples.py · semantics.py

看之前，先知道這些

分開「已確認的事實」和「觀察／待確認」。

✅ 已確認事實

  • 澄清先於模型：命中 5 組關鍵字之一（且沒有排除詞）就回傳 text、clarify、done，不初始化 LLM。
    backend/app/core/agent.py:70–150
  • 補脈絡順序：Schema 預選（top-3）→ 相似範例（top-3）→ 詞語映射 → 欄位描述 → JOIN 提示；各項失敗只記錄，不中斷主流程。
    agent.py:172–222
  • 守衛：sqlglot 解析 AST；只放行單一 SELECT；系統表 app_settings／chat_sessions／chat_messages／alembic_version 一律擋下；Agent 工具呼叫、/execute、範例存檔都會過它。
    core/sql_guard.py · agent.py:331 · database.py:510 · sample_store.py:153
  • 獨立 Embedding：embed_base_url、embed_api_key 留空時沿用主端點與金鑰；embed_model 不沿用。
    models/settings.py:24–32 · test_slice1_embed_settings.py
  • JOIN 提示以 BFS 在「已宣告外鍵」圖上找最短路徑。
    core/graph_path.py · test_slice3_graph_join.py
  • API Key 存 settings.db，與業務庫實體隔離；啟動時會把舊的 app_settings 搬離業務庫。
    main.py（lifespan）· connection.py
  • 部署：Dockerfile 兩階段、PORT=7860，已從 Vercel（10 秒逾時）遷到 Hugging Face Spaces Docker。
    Dockerfile · MIGRATION_LOG_20260422.md

⚠️ 觀察／待確認

  • 版本：2.0 功能只在 backend-overhaul 分支（HEAD 2ad5146），尚未併入 main。
  • README 過時：仍寫「阿里雲百炼 Qwen3、Phase 1–4」，與程式（OpenAI 相容、多供應商設定）不符；本頁以程式為準。
  • 澄清很「硬」：固定關鍵字＋內建選項，不依資料庫欄位產生（例：「會員等級為 VIP」在範例庫沒有對應欄位）。
  • 向量檢索在實拍環境沒生效：主端點對 embedding 模型回 503，Schema 索引建置失敗，樣本檢索退回 Jaccard。
  • JOIN 提示在實拍環境沒產生：範例資料 0 個外鍵（4 條推測關聯不進 BFS）。
  • 守衛屬既有機制（升級規格書標為 1.0），無單元測試；本頁案例為程式推演，未實跑。
  • 實拍畫面：AI 回覆顯示為原始 markdown 表；圖表標題「平均值統計」為規則式備援標題，可能代表該次走了備援（推測）。
  • 示意內容：BFS 範例（orders／customers／regions）取自單元測試，非實際資料庫；「完成 → completed」為後台的示意範例。
  • 部署：HF Space NL2SQLAgent-HF-v2 存在，但無法確認部署的是 2.0 分支。
  • 影片：旁白發音與音量未經人耳確認；最後一輪獨立評審（critic）因用量額度未執行；SFX 為量測而非實聽。
  • 未實測：本頁「怎麼跑起來」依 README 與 Dockerfile 整理，沒有啟動服務。
